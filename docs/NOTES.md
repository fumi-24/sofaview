## 2. 調査結果（2026-10-18）

### 2.1 実験環境

- クラウドセッションのサンドボックス（Linux）。Node 22、Playwright 1.56.1（`/opt/node-tools/node_modules`）、Chromium 141.0.7390.37（`/opt/pw-browsers/chromium-1194`）。
- 外部通信はプロキシ経由。Chromium には `launch({ proxy: { server: process.env.HTTPS_PROXY } })` を渡す。
- **制約**：日本国外IP、Widevine なし。→ **TVer の再生は検証できない**。YouTube の再生は可（19 秒の動画が `readyState 4` で再生された）。

### 2.3 TVer

**フレームワーク・テーマ**

- Next.js（`#__next`、`__NEXT_DATA__`）。CSS Modules のクラス名（`Component_part__hash`、例 `ContentCard_root__tVcTy`）。ハッシュはビルドごとに変わる前提。
- `html lang="ja" class="light"`。CSS に `.dark{…}` のトークン定義があり、**ダークテーマが標準機能として存在**する。インラインスクリプトが `localStorage.appearanceMode`（`dark`／`light`／`system`、未設定は `light`）を読んで `html` のクラスを決める ✔。
- デザイントークン例：`--Background_Primary`、`--Border_Function_Focused`、`--color-state-focused`（sky-500）、`--color-surface-background-primary`。

**レイアウト**（1920px 幅、拡大なし）

- `header`：`position: fixed` の**全画面オーバーレイ**（高さ＝ビューポート）。ハンバーガー（「メニューを開く・閉じる」）、ロゴリンク、検索フォーム（`input.SearchForm_keyword`）、設定（`Visitor_icon`）。
- `nav`：`position: sticky; top: 72px`、`overflow: auto`、幅 180px。項目：ホーム（`/`）、さがす（`/search`）、リアルタイム（`/live`）、カテゴリ（`/categories/drama` `variety` `anime` `news` `sports`）。
- `main`：コンテンツ。`footer`：規約・SNS・ヘルプ等のリンク。ページスクロールは `html`（ドキュメント）。スクロールすると、固定ヘッダーの検索フォーム・設定ボタンがコンテンツの上に重なって表示される ✔（→ TV 用スキンでは隠す方針の根拠）。

**ホーム `/`**

- DOM 上に約 50 セクション（`h3` が 49）。ページ全高 13,316px。`a[href]` 655、`button` 102、`[tabindex]` はわずか 9。→ **Tab 移動は現実的でなく、空間ナビが必須**。
- 各セクションは横スクロールの `ul.Carousel_list`（`overflow-x` コンテナ、`scrollWidth` 約 1,900〜4,100px／`clientWidth` 1,740px）＞ `li.Carousel_item` ＞ `a.ContentCard_root`（`EpisodeCard_root`／`SeriesCard_root`）。
- ビルボード（`BillboardList_*`）：ループ型。~~DOM に複製があり DOM 順の先頭が右端にある~~ は**誤りだった**（3.11）。複製のスライドはなく、`li.keen-slider__slide` とページ送りのボタンが同じ数（9）あるだけで、位置は毎フレームの `transform` で決まる。
- 矢印ボタン（`Carousel_control`）：スクリーンショット上は非表示（ホバー時のみ表示と推測 🔶）。アプリ誘導バナー（`AppBanner_link`）。
- 広告・計測系の要素（`freak-out_container`、`DmpEmbedTag` ほか）。

### 2.4 試作（使い捨て → 製品化済み）

調査中に作った使い捨ての試作。コードは捨て、検証した内容を実装（3章）に取り込んだ。

**試作A：YouTube UA 偽装拡張**（MV3、DNR＋MAIN world）

- 結果：`youtube.com/tv` が Playwright の UA 指定なしで TV UI として起動 ✔。`navigator.userAgent` が Tizen UA、`navigator.userAgentData` が `undefined`。
- → 実装：`extension/rules/youtube-ua.json`（ヘッダ）、`extension/sites/youtube/ua-main.js`（`navigator`）。

**試作B：TVer スキン＋ズーム＋空間ナビ**

- `permissions: []` のまま、Service Worker から `chrome.tabs.setZoom(tabId, 1.5)` が動いた ✔。1920×1080 で `innerWidth=1280`、`innerHeight=720`、`devicePixelRatio=1.5`。
- `localStorage.appearanceMode = "dark"` を `document_start` で設定して `html.dark` になった ✔。マニフェストの `css` で非表示・フォーカス枠が効いた ✔。
- ダークテーマ＋ズーム 150% で、TVer がすでに **TV らしい見た目**（暗い背景、白いピルでハイライトされる左レール、大きなカード）になった ✔。レールの白ピルは /tv のガイドとほぼ同じ見た目。
- 方向キーのナビ試作：ビルボード → バナー → ランキング行 → レールまで移動できた ✔。試作の課題は実装で解決した（3.2）：①ワイドなカードから ← → を押すと隣のカードでなく「すべてみる」リンクに飛ぶ → 重なり判定を 2 段階の採点に ②該当なしの方向でも遠くの要素へ飛ぶ → 移動しない ③TVer 標準の青いフォーカスリングと二重になる → トークンを透明にして独自の枠だけ描く。
- → 実装：`extension/sites/tver/`、`extension/common/spatial-nav.js`、`extension/common/zoom.js`。

### 3.2 実装した主な仕組み（要点）

- **YouTube /tv 起動**：DNR `modifyHeaders` で `||www.youtube.com/tv`（main_frame／sub_frame）の `User-Agent` を Tizen 6.0 にし、MAIN world の content script で `navigator.userAgent`／`appVersion`／`userAgentData` を揃える。Home／BrowserHome は capture で受け、Service Worker 経由でハブへ。通常 URL の転送（`yt-redirect`）は既定オフの別ルールセットで、設定で切り替える。

### 3.6 CI で 1 回だけ落ちた E2E の原因：画面倍率の競合（2026-10-19）

PR #1 の CI（GitHub Actions）で、同じコミットの 2 つの実行のうち 1 つで E2E が 1 件だけ落ちた（`tver-nav`「行内の左右・行間の上下」。2 行目の同じ列が `epv3` のはずが `epv2`）。もう 1 つの実行と手元の繰り返し（無負荷 8 回、負荷あり 55 回）では再現しなかった。

**原因の絞り込み**：`epv2` になるのは、1 行目が横に 1 枚分ほどスクロールされているとき（見た目の列が 1 つ左の `epv2` に当たる）。TVer の再現ページでそうなるのは、画面が狭いとき、つまり倍率が 1.5 倍より大きいとき（計算上 2.25 倍で一致）。→ 倍率が過大になった疑い。

**再現**：画面倍率の要求の瞬間に `innerHeight` と DPR を記録し、CPU 負荷（8 本）をかけてページを 200 回開いた。
- 修正前：4 回で、要求の時点の `innerHeight` が 1080・DPR が 1（ページ側に倍率が未反映）なのに、Service Worker の `tabs.getZoom` は 1.5 を返し、**2.25 倍を適用**（最終の `innerHeight` は 480）。次のページ読み込みで自然に直る。
- 修正後：200 回すべて最終の `innerHeight` が 720。

**なぜ起きるか**：ページ側の `innerHeight`（レンダラ）とタブの倍率（ブラウザ）は別々のタイミングで読まれる。tver.jp の倍率は Chromium が保存するので、2 ページ目以降は読み込み時にタブがすでに 1.5 倍だが、ページ側への反映が DOMContentLoaded に間に合わないことがある。前に直した「要求の同時送信」（5.1）とは別の経路。実利用でも、まれに（負荷が高い読み込みで）画面が 2.25 倍になり、次の読み込みまで戻らない不具合だった。

**対策**（SPEC 7.3）：(a) 最初の標本は、DPR ÷ タブの倍率が 0.9 未満なら矛盾として使わない。(b) 要求は順番に出し、倍率を変えたら落ち着いてから再確認する（`SV.zoom.fit`、最大 3 回）。TVer の E2E は、倍率の確認が終わる（`data-sv-zoom="done"`）まで待ってから操作する（`tverReady`）。

**テスト**：単体（仮想時間で、古い標本・矛盾を検出できない標本・打ち切り）、E2E `tver-zoom`（Service Worker の `getZoom` を 1 回だけ偽の値にして、食い違いを決まった形で再現。修正前は最終の高さが 480 になり失敗することを確認）。


### 3.7 実サイトのスモークで見つかった不具合：パンくずが初期フォーカスを奪う（2026-10-19）

3.6 の修正後にライブスモークを回すと、「TVer 番組ページ・エピソードページ」が（全体を通して実行したときに）毎回失敗した。単独で実行すると通る。調べると、実サイトの番組ページでは **ページ下部の「パンくず」（`div.AppLayout_breadcrumb` ＞ `ul.Breadcrumb_list` ＞ `li` ＞ `a`。`main` の外）にフォーカスが移っていた**。

- **初期フォーカス**：番組の内容が描画される前は、フォーカス候補がパンくずだけになる。「コンテンツ領域の候補が現れるまで待つ」条件（`requireRegion: 'content'`）は、`main` の外のパンくずも「コンテンツ」とみなして通してしまい、ページ下部のパンくずにフォーカスして画面を最下部までスクロールしていた（このときの座標は y=4964 などになる）。
- **↓ キー**：ビルボードのバナーから ↓ で、番組のカードではなくパンくずの「ドラマ」に移ることがあった。
- 全体を通して実行すると毎回失敗し、単独だと通ったのは、2 ページ目以降は保存済みの倍率で読み込まれ、描画のタイミングが変わるため。実サイトの番組によってもパンくずの有無・描画順が変わる。

**対策**：(a) パンくずを除外（`SEL.breadcrumb`。URL・属性に頼れないのでクラスの断片と `aria-label="breadcrumb"`）。(b) 初期フォーカスは、4 秒までは `main` の内側の候補を待つ（`focusInitial` の `within`）。未知の「`main` の外の補助リンク」でも同じ不具合が起きないようにするため。`main` のないページでも、4 秒後には外の候補を選べる。

**テスト**：再現ページ（実サイトと同じ位置にパンくずを追加）で、除外テスト・描画遅延の初期フォーカスのテストが修正前は失敗することを確認。さらに `tver-spa` に「`main` の外の除外されないリンクがあっても描画前の初期フォーカスにならない」を追加。ライブスモークは 2 回連続で 7 件通過。

**教訓**：再現ページ（フィクスチャ）は、実サイトの構造を縮小して作るので、実サイトにあって再現ページにない要素は検出できない。実サイトのスモークは、その差を見つける役目（3.4）。


### 3.8 実機の Chrome で見つかった不具合：ビルボード（注目作品）のリングが見えない・← → が効かない（2026-10-19）

ユーザーが普通の Chrome（拡張機能ページから読み込み）で試して報告：「一番上の注目作品でカーソルが表示されない」「そこで右左ができない」「ページを切り替えるとカーソルが勝手にどこかへ行く」。実サイトで再現して原因を確かめた。

**実サイトのビルボードの構造**（再現ページには無かった）：`ul.keen-slider`（`overflow: clip`）＞ `li.Slider_item.keen-slider__slide` ＞ `div` ＞ `a.BillboardList_link` ＞ `img`。**自動で回る**（約 4 秒ごと）ループ型で、スライドは `transform` で動く（スクロールではない）。画面に出ないページ送りのボタン `BillboardList_selectorItem`（スライドと同じ順・同じ数）があり、`click()` するとスライドが切り替わる ✔。`mouseover` を送っても自動送りは止まらない ✔。

**原因**
1. **リングが見えない**：リンクの `outline`（内側 −6px）は、中の `img`（絶対配置）に上から隠れる。計算上は「白 4px の実線」なのに画面には出ない（スクリーンショットで確認）。`elementsFromPoint` の最前面が `img`。
2. **← → が効かない**：座標ナビがフォーカスを動かすのは、画面外（`overflow: clip` の外）のスライド。スライダーは `scrollLeft` で動かせないので、フォーカスだけが見えない所へ行く。先頭の ← は、前のスライドが「ループで右端」にあるため、左の候補がなくレールへ出る。
3. **自動送り**：フォーカスしたスライドが約 4 秒後に画面外へ回り、フォーカスが残ったまま見えなくなる（「カーソルがどこかへ行く」）。ホーム・カテゴリ・ランキングなど、ビルボードがあるページは初期フォーカスがビルボードなので、**ページを切り替えるたびに起きる**。
4. （同時に見つかった）番組ページの初期フォーカスが、**新しいタブで開くバナー**（`target="_blank"`）や、`schedule-drama.tver.jp` のような**別サブドメイン**（拡張が動かない）になることがあった。

**対策**（SPEC 9.4）：リングを疑似要素（スライド `li::after`、画像の上）で描く。← → はスライド 1 枚ずつ。スライドにフォーカスが来たらボタンを `click()` して表示位置へ回す。自動送りで変わったらフォーカスも追う。`target="_blank"` と `tver.jp` 以外（サブドメインを含む）のリンクは除外。

**テスト**：実サイトの構造を再現したページ（`homeKeenHtml`）と `tver-billboard`（6 件）。修正前の拡張機能では 6 件中 5 件が失敗する（リングの位置の画素が画像の色のまま／← が効かない／フォーカスが表示外に 3.5 秒以上残る／↑ で戻っても回らない／新しいタブのバナーにフォーカス）。

**「ページを切り替えるとカーソルが勝手にどこかへ行く」について**：上の 3. が主因と考えている（実機で確認してもらう）。レールで項目を選んだあと、遷移先が描画されるとフォーカスが自動でコンテンツへ移る動作は設計どおりとしていたが、ユーザーが「選んだあともカーソルが勝手に動く」と指摘したため、**フォーカスはレールに残す**仕様に変更した（SPEC 9.4「レールで Enter」。→ で新しいページの最初の要素へ入る）。

- 表示のタイマー（React の状態）：既定は 2.5 秒。操作盤か操作できる要素にフォーカス・マウスが乗ると 30 秒。操作盤内の Esc で即隠す。**一時停止・終了とは連動しない**。クラスを書き換えて偽装しても、React が持っているので効かない。
- キー：`document` の keydown（**バブリング**）。操作できる要素にフォーカスがあると、Space/Enter・矢印は何もせず（ボタン本来の動き）、それ以外では Space/Enter が再生/一時停止、← → が ±10 秒（`player.currentTime`）、↑ ↓ が音量 ±0.05、`f` が全画面、`m` がミュート。

**旧方式が実サイトで起こしていた干渉**（実際に再現した）

1. `<html>` を全画面にしていた。TVer 自身の全画面（`[js-fullscreen-target]`）とは別になり、TVer の `data-fullscreen` が `html` でも true になり、**TVer の `f` キーが拡張の全画面を終えて HUD を閉じた**。
2. 擬似フルスクリーンの `position: fixed` が `PlayerLayout_jail` の**マスクに切り取られ**、映像は元の 752×423 のまま。HUD だけが全面に出た（「見た目が全然違う」の主因）。`verifyFullscreen` が対象の矩形だけを見ていたので成功と判定していた。
3. `visibility: hidden` で他を隠したため、**TVer 自身の操作盤・次のエピソードの案内・広告の表示が消えた**（操作盤は `.video-js` の兄弟なので、プレイヤーの子孫ではない）。
4. HUD は偽の Video.js（`.vjs-control-bar`）を前提に作っていて、`<video>` を直接操作していた。**初回のアンケートを飛ばして再生できてしまった**。
5. 閉じたあとの ↓ のスクロール・戻る（`history.back()`）で、TVer がミニプレイヤーに切り替えた（音が鳴り続けた）。
6. `playing` のたびに HUD と全画面を開き直した（広告・再開でも）。全画面はユーザー操作なしでは拒否されるので、擬似のまま（＝上の 2 の崩れた表示）だった。
7. 再現ページが偽の Video.js だったので、上のどれも自動テストで捕まえられなかった。

**方針**（ユーザーの「元の CSS をいじる」）：**TVer 自身のプレイヤーと全画面をそのまま使い**、見た目は CSS、/tv の状態遷移だけを拡張が持つ（SPEC 7.5・9.5）。

- 操作盤の出し入れは拡張の状態で決める（`html[data-sv-ui]` で `opacity`）。TVer のタイマーは使わない。**TVer の進行バーはマウス専用**で、スクラブの目標を表せないので、タイトル・バー・時間・スクラブの時刻は読み取り専用の覆いに描き直す。
- 全画面は TVer の全画面ボタンを `click()`（ユーザー操作の窓の中）。劇場表示（CSS）を常に当てるので、全画面でなくても・解除されても同じ見た目。`jail` のマスクを外す。
- スクラブの確定は `video.currentTime` を設定（TVer の「10 秒進む」を何十回も押さない）。再生・一時停止・速度・画質・全画面・次のエピソードは TVer 自身のボタンを押す。
- 離れるときは、ミニプレイヤーが出たらすぐ「閉じる」を押して破棄する。

**実装・テストでわかったこと**

- **ポップアップの矢印は選択ではなくフォーカス移動だけ**（実プレイヤーで確認。Radix の RadioGroup は、矢印キーのフラグを `document` のリスナーで立てるため、フォーカスが動く時点では立っていない）。Enter も何もしない。→ OK で拡張がフォーカス中の項目を `click()` して Esc を渡す。調査メモの「↑ ↓ で選ばれる」は、フォーカスの動きを見ただけの誤りだった。
- **再生速度のポップアップが開くと、ボタンとツールチップの間にポップアップが入る**。「ボタンの直後のツールチップを隠す」（`+`）が効かなくなる → `~`。
- **覆いの重なり**：`PlayerLayout_jail` は `isolation: isolate` で、中の操作盤はその層に閉じる。覆いを host の直下（`z-index: 3`）に置くと、操作盤のポップアップが覆い（時間の表示）の下になった → 覆いを**操作盤の直前（同じ親）**に置き、覆い 1・操作盤 2 にする。
- **Playwright の `page.evaluate` は CDP のユーザー操作として扱われ、約 5 秒の「操作の窓」ができる**。「操作なしでは全画面にしない」を確かめるテストは、再生が始まるまで `evaluate` せずに待つ（`waitForTimeout`）。ポーリングしていると、窓が開き続けて全画面が入る。
- **全画面中の Esc**：Chrome は要素の全画面中の Esc を奪って全画面を終える（ヘッドレスでは奪わない）。**Keyboard Lock**（`navigator.keyboard.lock(['Escape'])`）で拡張が受ける（ロック中は Esc の長押しで全画面を終える）。実機で確認 ❔。
- **「次のエピソード」の「閉じる」は、自動再生を止めて、プレイヤーを初期状態（ポスター）へ戻す**（全画面も TVer 自身が終える）。BACK 1 回目でそれを押す。ポスターに戻ったあとの BACK は普通の「前のページへ」、OK は見直し。案内が残っているとき（推薦の取得待ちなど）の 2 回目の BACK は画面を離れる（そうしないと BACK が何度でも同じ案内に戻って、離れられない）。**ソースだけを読んで「カウントダウンを止めるだけ」と書いていたのは誤りで、実サイトで押して分かった**（MAIN world に入れたスクリプトで `exitFullscreen()`・`video.load()` の呼び出しとその呼び出し元（スタック）を記録すると、誰が何をしたか分かる）。
- **再現ページ**（`tests/fixtures/tver-player.mjs`）：実サイトの構造・CSS の性質（マスク・`opacity` のトランジション・tabindex・`data-fullscreen`）・JS の挙動（表示タイマー・`document` の keydown・全画面・Radix 風のポップアップ・ミニプレイヤー・次のエピソード）を書き直したもの。**実サイトの CSS・JS はそのまま写していない**（再配布しないため）。`window.__fx`（`log` / `navigations` / `state()`）で TVer 側に起きたことを観測できる。クラス名の全置換（`tver-resilience`）で「サイトが作り直された」状況も再現する。

**テスト**：単体（`watch-core` 25 件、CSS の規約 3 件）、E2E `tver-watch` 29 件・`tver-resilience` のエピソード 4 件、ライブ（実プレイヤー）1 件。旧方式を同じテストに当てると、マスクで映像が小さいまま・操作盤が `visibility: hidden` になる。

**実機で確認すること**（SPEC 9.5・本書 4 章 #7）：全画面中の Esc（Keyboard Lock）、約 5 秒の窓、広告（`strp-ad-module` は z-index 10000）、リモコンの `key`/`code`、DRM、初回のアンケート（文字入力が要る）。ライブ（`/live`）の視聴画面は、操作盤が未確認なので対象外。

### 3.10d 初回アンケートの自動入力・マウスカーソルの自動非表示（2026-10-20）

- **実サイトのアンケート**（実測）：`form[id^="questionnaire-"]` の中に、誕生年（`name=birthYear`・`maxlength=4`・例 `2000`）、誕生月（`birthMonth`・2 桁・例 `4`）、性別（`div[role=radiogroup]` に `button[role=radio]` が 3 つ（値 1・2・9）＋ 隠しの `input[type=radio]`）、郵便番号（`postCode`・7 桁・例 `1050004`）。欄ごとに「削除」ボタン。**`inputmode` はない**（→ 例が数字だけなら数字キー）。**「閉じる」「回答する」（`button[type=submit]`）はフォームの外**（モーダルの下の段）。
- **落とし穴**：(1) Radix のラジオは Enter では選べない（ポップアップの項目と同じ）→ OK でクリック。(2) 「回答する」を `form` の中で探すと見つからない → `[role=dialog]` の中で探す。(3) 流れの途中で次の欄へ移るのが速いと、前の欄のキーボードを閉じる処理と競合する → 100〜200ms 待つ。(4) Playwright のテストは、キーボードが画面を覆うので、直接クリックする前に Esc で閉じる（ライブテストの `answerQuestionnaire`）。
- **マウスカーソル**：以前は常に `cursor: none`。`common/cursor.js` で、読み込み直後は隠し、本物のマウスの `mousemove`（位置が変わったもの）・`mousedown`・`wheel` で出し、最後から 3 秒で隠す。

- **フォーカストラップ（2026-10-20 実機の不具合）**: アンケートのモーダルは Radix の `FocusScope` で、ダイアログの外へ移したフォーカスを中の最後の欄へ戻す。画面上のキーボードが `<body>` の直下にあると、誕生年の 4 桁目でサイトが誕生月へフォーカスを移した後、キーへの `focus()` が戻されて、矢印・OK の見た目の操作ができなくなる（キーイベント自体は OSK が受けている）。対策は、(1) 入力欄のダイアログの中にキーボードを置く（`osk.open` の `host`。ダイアログに transform はなく、位置は変わらない）、(2) 文字を入れたあと、フォーカスがキーボードの外にあれば取り戻す。

### 3.11 ビルボード（注目作品）：ラグ・左で一周・連打でずれる（2026-10-19）

ユーザーの要望：「ビルボードがラグい」「ビルボードで左にやる時に右に一周する」「連打するとカーソルが右にいっちゃう」。実サイトでフレームごとのログを取って調べた（実機の macOS Chrome ではなく、ソフトウェア描画のヘッドレス。時間は目安で、比は CPU 負荷の比として効く）。

**実サイトのビルボードの正体**：keen-slider（`loop: true`・`renderMode: custom`）。**複製のスライドはない**（`li.keen-slider__slide` とページ送りのボタンが同じ数）。`detailsChanged` が毎フレーム全スライドの `transform` / `min-width` / `z-index` を書く。アニメーションは 500ms の easeOutQuint 1 本。`next` / `prev` / `move` は**アニメーション中の呼び出しを黙って捨てる**。選択ボタンの `click` は `move(i)` で、**必ず前向きの距離**（`i−1` へ行くには n−1 枚進んで一周する）。自動送りは `setTimeout(next, 5000)` で、止めるのは keen の `stop` / `reset` / `restart` のイベントだけ（サイト自身が使うのは広告スライドのときだけ）。ホバー・フォーカス・キーのハンドラはない。インスタンスは React の fiber のフック（`useRef` の `current`）から取れる。

| 症状 | 原因 | 対策 |
|---|---|---|
| **ラグい** | 自分で書いた CSS の `:has()` 2 つ（`html:has(nav:focus-within) main` と `.keen-slider__slide:has(a:focus)::after`）。約 8,000 要素の DOM で、フォーカスの移動・class の切り替えのたびに 100〜140ms のスタイル再計算。キー 1 回で 3 回（keydown の中央値 263ms）。ビルボードだけでなく全部の移動が遅かった | 根（html/body）やスライドを基点にした `:has()` をやめる。兄弟セレクタ（`nav:focus-within ~ main`）と、リンク自身の `::after`。フォーカス 217ms → 0.6ms、keydown 263ms → 9ms。`tests/unit/tver-css.test.js` で再発を防ぐ |
| **左で一周** | 選択ボタンの `click`（前向きだけ）で動かしていた。← = +8 枚・500ms。素早い ← 12 回で +60 枚 | MAIN world の橋（`sites/tver/billboard-main.js`）が、サイトと同じ keen-slider の `moveToIdx`（最短経路・回転中でも向きを変えられる）を呼ぶ。← = ちょうど −1 枚 |
| **連打でずれる** | 最終状態が間違うのではなく、**入力が溜まって処理が遅れた**（1 秒押して 17 回ぶんが 4.3 秒かけて処理された）。`RepeatGate` は処理時刻で判定するので 1 つも捨てなかった | イベントの発生から 150ms を超えた押しっぱなしのリピートは捨てる（`staleMs`）。ビルボードの送りは 180ms 間隔まで。**目標は 1 つ（フォーカスしているスライド）**で、`go(i)` は冪等 |
| 自動送り | フォーカスしたスライドが回って見えなくなる | フォーカスがある間は橋で自動送りを止める（`stop` / `restart`）。橋が無いときは、自動送りに追従する |

**テスト**：`tver-billboard-bridge`（橋の挙動）、`tver-billboard`（リング・← →・ループ・連打・自動送り）。連打は 60ms 間隔 12 回・キーリピート・ランダムな間隔で 56 回以上、最後のフォーカス・表示・`moveToIdx` の目標が一致（失敗 0）。

### 3.12 スマホのリモコン（2026-10-20）

要望：「スマホから操作したい」。条件は「拡張機能だけ・GitHub だけ・誰でも使える」。自前の中継サーバーや、スマホ側のアプリは使えない。

- **検討して使えなかった道**：テレビ側で待ち受ける（拡張は接続を受けられない）、スマホ側で待ち受ける（ブラウザのページはサーバーになれない）、GitHub で受け渡す（書き込みにログインが要る）、WebRTC（初回の仲介が要る）、カメラで読む（カメラがないテレビがある）。
- **使えた道**：YouTube /tv は、起動するとスマホのリモコンの受け取り先（Lounge の screen）として自分で登録する（`/api/lounge/pairing/generate_screen_id` → `get_lounge_token_batch` → `bc/bind` の長いポーリング）。スマホの YouTube アプリがつながると、十字キー・決定・戻るは `dpadCommand`（`key` = UP/DOWN/LEFT/RIGHT/ENTER/BACK）として届く。/tv のコードは、これを `document.activeElement` へキーイベント（`keyCode` 38/40/37/39/13/27）にして出す。
- **実測**（このサンドボックスで、スマホの代わりに REMOTE_CONTROL として `bc/bind` に dpadCommand を送った）：/tv のページに、`keydown`/`keyup` が **`isTrusted: false`・`key` なし・`keyCode` のみ**で出る。**`keyCode` はページ側で付けているため、拡張の isolated world からは読めない**（`remote-main.js` が MAIN world で読み、`postMessage` で渡す）。
- **経路**：`remote-main.js`（MAIN）→ `youtube/content.js`（`SV.remote.watchYoutube`）→ background（`sv:remote`）→ 前面の TVer・ハブのタブ（`sv:remoteKey`）→ `SV.remote.inject`。合成イベントなので `keys.js` の `shouldIgnore` に弾かれる。`SV.keys.allowSynthetic` で、リモコンが作ったイベントだけを通す。Enter は、合成イベントにブラウザ標準の動作（リンクを開く）が付かないので、`inject` が `click()` する。
- **ハブの url**：`tabs` 権限がないと、拡張自身のページ（ハブ）のタブは `url` が `null`。url が分からないタブへも送る（受け取れるのは拡張のページだけ）。
- **未確認（実機）**：本物のスマホのアプリでの操作、裏のタブが長時間休止・破棄されないか（`autoDiscardable: false` と Web Lock で対策済みのつもり）、アプリのリモコンの表示。

### 3.13 YouTube /tv で Esc を押すとブラウザが終了する（2026-10-20）

症状：キオスクで YouTube /tv からホームへ戻ろうとして Esc を（長押しで）押すと、ブラウザごと終了した。
原因（実測）：/tv はトップ画面で「戻る」（Esc）を受けると、アプリを終わらせるつもりで `window.close()` を呼ぶ（Esc 4 回で 3 回）。履歴が 1 つだけのタブは script から閉じられるので、キオスクでタブが 1 つだと、これでブラウザが終了する。
対策：`sites/youtube/exit-main.js`（MAIN world）が `window.close` を差し替え、`postMessage` で知らせる。`content.js` がブラウザを閉じずにハブへ戻す（`SV.goHub`）。

## 5. ハマりどころ・知見

### 5.1 調査・実装で見つけた落とし穴

- **DNR の `regexFilter` は 2KB（コンパイル後）まで** ✔：`(?:.*&)?` を含む式（`v` が先頭でない `watch?x=…&v=ID` も拾う式）は「regexFilter が 2KB のメモリ上限を超える」としてルールごと無効になった。`v` が先頭の単純な式にして解決（`v` が先頭でない URL は非対応）。
- **Playwright の `route` を張った URL には DNR のリダイレクトが効かない** ✔：`route.fulfill` が先に応答するため。DNR の検証は `route` を張らない URL で行い、`/tv**` だけを再現ページにする。
- **画面倍率が二重に効いた** ✔：計算が「ページ側の `innerHeight`」と「タブの倍率（Service Worker が読む）」の積なので、2 つの標本が食い違うと過大な倍率（2.25 倍＝1.5×1.5）になる。(1) 要求を同時に 2 回送ると混ざる。(2) **読み込み直後は、ページ側にタブの保存済みの倍率がまだ反映されていない**ことがある（`innerHeight` 1080・DPR 1 のまま、タブは 1.5 倍）。(2) は 1 回しか送らなくても起き、CI の E2E が 1 回だけ落ちて発覚した（3.6）。要求を順番に出し、倍率を変えたら落ち着いてから再確認する（SPEC 7.3）。
- **スクリーンショットのズレ** ✔：`tabs.setZoom` を使うと、Playwright の `page.screenshot` はスクロール時にずれる（ズーム差×スクロール量。約 310px）。DOM 自体は正しい。見た目の検証は `deviceScaleFactor` エミュレーション（viewport 1280×720 @1.5）＋ズーム設定「変更しない」で行う。
- **Chromium は読み込んだ拡張のディレクトリに `_metadata/` を書く** ✔：リポジトリを汚すため、E2E は拡張を一時ディレクトリにコピーして読み込む。`.gitignore` にも追加。
- **Shadow DOM のホストに付けたインライン `all: initial` は `:host` ルールより強い** ✔：（旧 HUD で）文字が黒・セリフ体になった。文字の既定値（色・フォント）は内側の要素に付ける。HUD は廃止したが、Shadow DOM を使うときの注意として残す。
- **STREAKS Player の CSS は `.streaks-player:not(.strp-initialized)` の子を隠す** ✔：偽プレイヤーを差し込むときは `strp-initialized` などのクラスも付ける。実プレイヤーでは初期化後に付く ✔。
- **詳細度の逆転** ✔：レールの白ピル（`nav a:focus-visible`）が汎用リングに負けた → 汎用リング側を `:where()` で詳細度 0 にする。
- **独立してスクロールする行をまたぐ上下移動** ✔：行ごとに横スクロール量が違うため、列がずれる → 列（x）を粘着させ、スクロールで動いた分は遅延更新。横スクロールは即時（なめらかにすると座標が安定しない）。
- **フルロード後にフォーカスが失われる** ✔：TVer のリンクは通常のページ遷移になる場合がある → フォーカス記憶を `sessionStorage` にも保存して復元。
- **初期フォーカスがレールに落ちる** ✔：コンテンツの描画前に実行されるとレール（`nav`）の最初のリンクが対象になる → `requireRegion`（コンテンツ領域が現れるまで待つ）。ユーザーが操作した後は奪わない。
- **`sv:info` が応答しない** ✔：Service Worker から自分自身へ `sendMessage` しても自分のリスナーには届かない。拡張ページ（診断ページ）から送る。
- **キー割り当ての「すべて消す」が効かない** ✔：保存時に深いマージをしていたため、空の `bindings` を渡しても既存の割り当てが消えなかった → `save(patch, { replace: ['bindings'] })` で置き換える。
- **TVer 標準のフォーカスリングは `--color-state-focused` で描かれる** ✔：トークンを `transparent` にして、独自の白リングだけが見えるようにした。
- **ビルボードは DOM 順に頼らず座標で判定する**（複製はない。スライドの位置は `transform` で決まり、DOM 順と見た目の順が一致しないことがある。3.11）。
- **`scrollIntoView` の副作用**：祖先が全てスクロールされる。TVer は `header`（fixed）と `nav`（sticky）があるため自前スクロールにする。
- **`header` は全画面の固定オーバーレイ**：高さがビューポートと同じ。フォーカス候補の判定では要素の矩形・可視性で見る。
- **DNR の確認方法**：Playwright の request ログは書換え前のヘッダを表示する。起動できたか（`ytlr-app` の有無）で判断する。
- **UA の整合**：ヘッダと `navigator` を両方揃えた構成で動作確認した。片方だけの挙動は未確認。
- **YouTube /tv のルートで BACK**：アカウント選択に戻るだけで、それより先へは進まない ✔。ハブへは Home（または長押し BACK）。
- **YouTube /tv への深いリンク**：`#/watch?v=…` を直接開いても、初回（アカウント選択前）は選択画面に戻される。ログイン済みプロファイルなら有効と思われる ❔。
- **TVer の再生ページに「アプリで視聴する」ボタン**：サンドボックス（再生不可の状態）で表示された。実機で再生できるなら不要な可能性がある。現在は隠す（設定でオフ可）。
- **横スクロールで画面の外へ出た要素も、方向キーの候補になる** ✔：座標だけで選ぶため、別の行の見えない要素へ飛ぶことがある。同じ行／列に並ぶ候補 → 隣の領域 → 斜めの候補、の順にして避けている（3.5）。
- **テストで `element.focus()` を直接呼ばない** ✔：スクロールコンテナ内で一部しか見えない状態が残り、実際のキー操作では起きない状況になる（3.5）。
- **Service Worker の起動直後は `chrome.tabs` などが未定義のことがある** ✔：`serviceworker` イベントの直後に `sw.evaluate` すると、CI で 1 回だけ `Cannot read properties of undefined (reading 'setZoom')`。`launch()` が使えるまで待つ。
- **`html { overflow-x: clip }` は `position: sticky` を壊す** ✔：レールがスクロールで流れた。押し出された内容は、もともと `body` が `overflow-x: hidden` なので切れる。
- **`#__next` は `isolation: isolate`** ✔：外に置いた固定要素は、ヘッダーのロゴを含むアプリ全体の上に載る。重なりを細かく決めたい要素は `#__next` の中に置く（`#sv-topbar`）。
- **TVer の詳細ポップアップは Linux の Chromium では出ない** ✔：TVer の端末判定が Linux+Chrome を「Android PC」にするため。`sites/tver/ua-main.js` が Linux のときだけ UA を Windows の Chrome にする。この判定で `HeadlessChrome` を含む UA も Linux 扱いになる（E2E・ライブテストは影響を受ける）。
- **UA を変えると TVer の画面の一部が変わる** ✔：レールに「マイページ」が増える、番組ページの「アプリで視聴する」が「お気に入り登録」になる。ライブテストで再生ページに `video` 要素が増えることもある（`video[src]` で差し込んだ偽のものを指す）。
- **検索ピル（上部バー）が描画前の唯一のコンテンツ候補になる** ✔：初期フォーカスを奪う → `main` に操作できるものが描画されるまで候補から外す。また、行が上へ流れて隠れたあとは、固定のピルが上方向で幾何的に一番近くなり、前の行・ビルボードに戻れなくなる → 上に別の候補があるときはそちらを先に選ぶ（SPEC 9.4c）。
- **再現ページのレイアウトは実サイトに合わせる** ✔：`AppLayout_app` を CSS グリッド（`--side-column-width`）にして、`nav` を sticky・`#__next` を isolate にした。以前の「nav を float・main に margin-left」では、レールの幅や重なりの不具合を再現できなかった。
- **`mask-image` は `position: fixed` の子孫も切り取る** ✔：TVer の `PlayerLayout_jail`（角丸のクリップ）が、擬似フルスクリーンの映像を元の大きさのまま切り取っていた。TVer 自身は `:fullscreen` のときだけ外す。劇場表示は `mask-image: none` を当てる（3.10）。
- **`position: fixed` の中の `z-index` は、`isolation: isolate` の層に閉じる** ✔：`PlayerLayout_jail` の中の操作盤（ポップアップを含む）は、外の `z-index` に勝てない。重ねたい要素は同じ層（操作盤の隣）に置く（3.10）。
- **Playwright の `page.evaluate` はユーザー操作として扱われる**（約 5 秒の窓ができる）✔：「操作なしでは全画面にならない」を確かめるときは、その間 `evaluate` しない（3.10）。
- **Radix の RadioGroup は、矢印キーで選ばれない**（TVer の速度・画質）✔：フォーカスが動くだけ。選ぶのはクリック（Space は未確認）。Enter は何もしない（3.10）。
- **サイトの JS が持つ状態は、クラスを書き換えても変わらない** ✔：TVer の操作盤の表示（`VodController_active`）は React の状態。偽装は効かず、CSS（`opacity` の `!important`）で見え方だけを決める。
- **プロキシ**：この環境では `HTTPS_PROXY` 経由。Chromium には明示的に渡す。Node の `fetch` は環境変数を見ない（`NODE_USE_ENV_PROXY=1`）。

### 5.2 テストの書き方（再開する人向け）

- E2E のヘルパー：`tests/e2e/helpers.mjs`（`launch()` が拡張を一時ディレクトリにコピーして新ヘッドレスで読み込む。`press`・`active`・`until`）。
- TVer の再現ページ：`tests/fixtures/tver.mjs`（ホーム・さがす・エピソード・SPA）。実サイトの DOM を観察して作ったもの。TVer の DOM が変わったら、まずライブスモークで差を見てから直す。エピソードのプレイヤーは `tests/fixtures/tver-player.mjs`（実サイトの構造と挙動の再現。`window.__fx` で観測）。
- 再生の再現：`tests/fixtures/media/test.webm`（60 秒、128×72、71KB）を `<video>` に使う。
- 視聴画面の状態は `html[data-sv-ui]`（H/C/S）・`html[data-sv-focus]`（bar/row）に写る。TVer 側で起きたことは `window.__fx.log`（再現ページ）で見る。
- 実プレイヤーでの確認（ライブ）：`playback.api.streaks.jp` だけを偽の応答にして、実サイトの JS・Streaks SDK のまま再生させる（`tests/live/live.test.mjs` の `fakePlayback`。初回のアンケートにも答える）。
