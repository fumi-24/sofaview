## 1. 概要

### 1.1 目的

テレビにつないだ PC／ミニPC の Chromium 系ブラウザで、**YouTube と TVer をテレビのリモコンだけ**（十字キー・決定(Enter)・戻る(Esc)・Home など）で視聴できるようにする。マウスもキーボードも使わない。見た目と操作は **youtube.com/tv に寄せて、2サービスで共通化**する。

### 1.2 方式

Chromium 拡張機能（Manifest V3）。**見た目（スキン）は CSS を優先**する。リモコンで動かす部分（キー処理・フォーカス移動・視聴画面の操作・画面倍率）は CSS ではできないため JavaScript、YouTube の起動は DNR ルール＋JavaScript で行う（役割分担は 4.3）。

| 対象 | 方式 |
|---|---|
| YouTube | 公式の `youtube.com/tv`（TV 向け UI）をそのまま使う。拡張機能が TV 用 User-Agent を与えて起動させる ✅✔ |
| TVer | 既存サイトを CSS＋JS で /tv 風に再スキンする（ダークテーマ・10フィート表示・フォーカス枠・十字キー移動・左レール・**視聴画面は TVer 自身のプレイヤーを /tv の視聴画面と同じ見た目・操作に**）✅✔ |
| ハブ | YouTube / TVer を起動する共通ホーム。どの画面でも Home キーで戻れる ✅✔ |

### 1.3 利用シーン

```
電源ON → ブラウザ(キオスク)起動 → ハブ → [YouTube | TVer] を選ぶ → 視聴
                                   ▲                              │
                                   └───────── Home キー ───────────┘
```

## 4. 設計方針

### 4.1 決定事項

| ID | 方針 | 状態 |
|---|---|---|
| D1 | 配布形態は MV3 拡張機能。**ビルド不要**（素の JS/CSS、クラシックスクリプト＋名前空間 `SV`）。ロジックは UMD にして Node で単体テスト | 🔶✔ |
| D2 | YouTube は公式 `youtube.com/tv` を使う。UA 偽装は **DNR（ヘッダ書換え）＋ MAIN world スクリプト（`navigator` 上書き）** | ✅✔ |
| D3 | TVer は再スキン。**見た目は CSS 優先**。JS は (a) キー処理と空間ナビ (b) 視聴画面の操作（TVer 自身のプレイヤーを /tv と同じ状態遷移で動かす）(c) テーマ・ズーム設定 の用途に限る（用途は限るが、コード量は JS のほうが多い。4.3）| ✅✔ |
| D4 | 共通 UI の基準は youtube.com/tv の実測値（付録B）。CSS 変数 `--sv-*` として共有 | ✅✔ |
| D5 | サイト固有のセレクタは `sites/<site>/selectors.js` に集約。CSS Modules のハッシュ部分は前提にしない（`[class*="Name_part__"]`）| 🔶✔ |
| D6 | フォーカスは**実 DOM のフォーカス**（`element.focus()`）。見た目は CSS で定義（TVer は `a:focus{outline-width:0}` と全体リセットをしているため `:focus` を対象にする）。擬似フォーカス（独自の枠要素）は使わない | 🔶✔ |
| D7 | プレイヤーは **TVer 自身のものをそのまま使う**（自前のプレイヤー・HUD は作らない）。全画面は **TVer 自身の全画面ボタンを押す**（`[js-fullscreen-target]` に Fullscreen API。TVer の状態・`:fullscreen` の CSS がそのまま働く）。それに加えて、**同じ見た目の劇場表示（CSS）**を常に当てる（全画面が拒否・解除されても、画面いっぱいで同じ見た目）。設定でブラウザの全画面だけ切れる。**`<html>` を全画面にしない・`visibility` で他を隠さない**（旧方式は TVer 自身の全画面と二重になり、操作盤が消えた。NOTES 3.10）| ✔ |
| D8 | 設定は `chrome.storage.local`（`sv.settings`）。保存値は常に既定値とマージし、範囲チェックしてから使う | 🔶✔ |
| D9 | 空間ナビは自前実装（Chromium の `--enable-spatial-navigation` は現行ビルドでの有効性が不明のため使わない）| 🔶 |

### 4.2 「共通化」の定義

共通化は 3 層で行う。YouTube は公式 UI をそのまま使うため、**/tv を基準（リファレンス）にして他を寄せる**。

| 要素 | ハブ | YouTube /tv | TVer |
|---|---|---|---|
| 色・文字（デザイントークン） | 自前（`--sv-*`） | 公式（同系色） | TVer 標準ダークテーマ＋`--sv-*` で上書き |
| フォーカス表現 | 自前（白ピル／白枠） | 公式（白ピル） | `--sv-*` で /tv と同じ見た目に |
| 左レール | 自前 | 公式 | 既存 `nav` を再スキン |
| 視聴画面 | なし | 公式 | **TVer 自身のプレイヤー（操作盤）を CSS で /tv の視聴画面に**。出し入れ・スクラブは拡張の状態で決める（7.5）|
| キー操作（決定・戻る・ホーム） | `keys.js` | 公式＋HOME のみ拡張 | `keys.js` |
| 文字スケール | `--sv-u`（高さ÷45）| 公式が自動 ✔ | 拡張が `tabs.setZoom` ✔ |

> 📝 YouTube /tv は公式のまま使う ✅ ため、視聴画面の再スキンは **TVer 向け**（YouTube 側のプレイヤーは公式 UI）。

### 4.3 CSS と JS の役割分担

「基本は CSS」は**見た目（スキン）**について守っている。リモコンで動かす部分は CSS ではできないので JS を使い、YouTube の起動は DNR ルール（宣言的なヘッダ書換え）と JS で行う。用途は限っているが、**コード量は JS のほうが多い**（拡張本体＝ハブ画面を除く＝で CSS 約 1,000 行、JS 約 3,100 行）。

| 部分 | 手段 | 理由 |
|---|---|---|
| TVer の見た目：非表示・フォーカス枠・カードのリング・左レールの白ピル・視聴画面の配置（劇場表示・操作盤・ポップアップ）| **CSS**（`sites/tver/tver.css` `watch.css`、共通の `tokens.css` `base.css`）| 宣言だけで足りる |
| TVer のダークテーマ | JS（`localStorage.appearanceMode`）| TVer 標準のダークモードを使う（色を CSS で上書きしない）|
| 画面の拡大（10フィート表示）| JS（Service Worker の `tabs.setZoom`）| ブラウザのズームにすると、CSS の画面サイズ（メディアクエリ）ごと変わる |
| 十字キーの移動 | JS（`common/spatial-nav.js`）| TVer のホームはリンク約 655 個に `tabindex` が 9 個だけで、Tab 移動は成り立たない。CSS にフォーカス移動の指定はない |
| Home → ハブ、キー割り当て、リピート制御 | JS（`common/keys.js`、`background/service-worker.js`）| キー入力の処理 |
| 視聴画面の操作 | JS（`common/watch-core.js` = 状態遷移、`sites/tver/watch.js` = DOM との接続）。見た目は CSS（`watch.css`）| TVer のプレイヤーはマウス前提（進行バーは操作できない）。/tv の「操作画面・スクラブ」の状態を拡張が持ち、TVer のボタンを押して動かす |
| YouTube /tv の起動 | DNR ルール（`rules/youtube-ua.json`）＋ JS（`sites/youtube/ua-main.js`）| User-Agent を TV 端末にするため。見た目の CSS は、マウスカーソルを動かしていないときだけ隠す 1 行だけ（`common/cursor.js`・`common/base.css`） |

CSS は単独では動かない。ルールはすべて `html.sv-tv`（YouTube は `html.sv-yt`）の下に書いてあり、このクラスと、設定による切り替え（`sv-hide-header` `sv-hide-app-cta`）は JS が付ける。視聴画面の CSS（`watch.css`）は `html.sv-watch` と `html[data-sv-ui]`（H/C/S）`html[data-sv-focus]`（bar/row）の下に書き、これらは `watch.js` が付ける。

## 6. 入力仕様（リモコン）

### 6.1 論理アクションと既定キー

物理キーは `KeyboardEvent.key`（なければ `code`、最後に `keyCode`）で判定する。**実機のキーは ❔ 未確認**。診断ページ（6.4）で採取し、必要なら設定のキー割り当て（6.5）で追加する。

| 論理アクション | 既定の物理キー | 備考 |
|---|---|---|
| UP / DOWN / LEFT / RIGHT | `ArrowUp` `ArrowDown` `ArrowLeft` `ArrowRight` | 長押しでリピート（上限 12回/秒）✔ |
| OK | `Enter` `NumpadEnter` | |
| BACK | `Escape` `Backspace` `BrowserBack` `GoBack` | Chrome は Backspace で戻らないため拡張が処理 |
| HOME | `Home` `BrowserHome` | **どの画面でもハブへ** ✅✔ |
| PLAY_PAUSE / PLAY / PAUSE / STOP | `MediaPlayPause` / `MediaPlay` / `MediaPause` / `MediaStop`（視聴画面では `Space` も再生／一時停止）| STOP は視聴画面を離れる |
| SEEK_BACK / SEEK_FWD | `MediaRewind` / `MediaFastForward` | 視聴画面のみ。スクラブを始め、1 回ごとに 10 秒（7.5）|
| PREV / NEXT | `MediaTrackPrevious` / `MediaTrackNext` | 割り当て済み・未使用（前／次のエピソードは次フェーズ）|
| MENU | `ContextMenu` `Info` | 視聴画面では操作画面を出す |
| PAGE_UP / PAGE_DOWN | `PageUp` / `PageDown` | 割り当て済み・未使用 |
| RED / GREEN / YELLOW / BLUE | `ColorF0Red` `ColorF1Green` `ColorF2Yellow` `ColorF3Blue` | 予約 |

`key` が `Unidentified` のときだけ、`keyCode` の予備表（Tizen の戻る 10009、webOS の戻る 461、再生 415、停止 413、早送り 417、巻き戻し 412、色キー 403〜406、`BrowserBack` 166、`BrowserHome` 172）を使う ✔。

### 6.2 共通ルール

1. `window` の **capture フェーズ**で `keydown` を処理する（`run_at: document_start`）✔。
2. `isTrusted` でないイベント、`Ctrl` / `Alt` / `Meta` 併用、IME 変換中は無視 ✔。
3. `input` / `textarea` / `[contenteditable]` にフォーカス中は HOME 以外を処理しない ✔。
4. 処理したキーは `preventDefault()` ＋ `stopImmediatePropagation()` してサイト側に渡さない ✔。ただし **「サイトに任せる」コンテキスト**（YouTube /tv の方向・決定・戻る、TVer で開いているダイアログ内の Esc、フォーカス中のリンク・ボタンの Enter）では何もしない ✔。
5. `repeat` を許可するのは方向キーと SEEK のみ。OK／BACK／HOME の長押しリピートは握りつぶす ✔。方向キーのリピートは 1 秒あたり最大 12 回 ✔。
6. Home・BrowserHome・Backspace の既定動作（ページ先頭へスクロール・ブラウザのホーム／戻る）は `preventDefault()` で止める ✔。
7. 設定で「戻るキーの長押しでホームへ」をオンにすると、BACK を既定 800ms 以上押し続けたときにハブへ戻る（既定オフ）✔。

| TVer ブラウズ | 拡張の空間ナビ | フォーカス中のリンク・ボタンを開く（再生前のポスターの再生ボタンなら、TVer 自身が再生を始める）| ①開いているダイアログはサイトに閉じてもらう ②ホーム（`/`）またはこのタブの履歴が 1 件ならハブへ ③それ以外は `history.back()` | ハブへ |

### 6.4 キー診断（`hub/diag.html`）

押したキーの `key` / `code` / `keyCode` / `location` / `repeat`、前回の入力からの経過時間（キーリピート間隔の確認用）、割り当て済みの動作（なければ「未割り当て」）、履歴（8 件）、環境（UA・画面・ウィンドウ・DPR・拡張 ID）を表示する ✔。診断中は Home・Backspace などの既定動作を止める。**戻る／ホームを 3 回続けて押すとハブへ戻る** ✔。

### 6.5 キー割り当て（`hub/keys.html`）

動作を選んで Enter → リモコンのボタンを押すだけで登録する（文字入力不要）✔。既定のキーは消えず**追加**になる（誤設定でリモコンが効かなくなるのを避ける）。Esc で取り消し、8 秒で自動取消。「追加した割り当てをすべて消す」は 2 回 Enter。設定は TVer・YouTube・ハブ・設定ページのすべてに反映される ✔。

### 7.3 10フィート表示（スケール）

**基準：CSS ビューポート高さ ≒ 720px 相当**（1080p で 150%、4K で 300% 表示）。

| 対象 | 方法 |
|---|---|
| YouTube /tv | 公式が自動でスケールする（root フォント = 高さ÷45）✔。**拡張は何もしない** |
| TVer | Service Worker が `chrome.tabs.setZoom` で調整 ✔（追加権限なし。1920×1080 で CSS ビューポート 1280×720・DPR 1.5 になることを E2E で確認）|
| ハブ・視聴画面 | 自前。`--sv-u: calc(100vh / 45)`（1080p で 24px）を単位にする。視聴画面は **`--wu` = min(画面幅 ÷ 80, 画面高さ ÷ 45)**（/tv の UI は画面の中央の 80 x 45 の舞台に描かれる。16:9 なら `--sv-u` と同じ）✔ |

- 計算式：`zoom = clamp(round20(innerHeight × 現在のタブ倍率 ÷ targetHeight), 1, 4)`（`round20` は 0.05 刻み）。すでに 720 前後なら 1 倍で何もしない ✔。
- **要求は順番に出し、倍率を変えたら落ち着いてから確認する**（`SV.zoom.fit`。1 ページ読み込みにつき 1 回始め、DOMContentLoaded 後）。計算式は「ページ側の `innerHeight`」と「タブの倍率（Service Worker が読む）」を掛けるため、2 つの標本が食い違うと二重に拡大される ✔。食い違いは 2 通りで起きた：
  1. 要求を 2 回同時に送った（ズーム適用前の `innerHeight` と適用後のタブ倍率が混ざった）。
  2. **ページの読み込み直後**、ページ側にはタブの倍率（前のページで保存された 1.5 倍）がまだ反映されておらず、`innerHeight` が 1080・DPR が 1 のまま要求が届いた。タブは 1.5 倍と答えるので 2.25 倍にしてしまった（高負荷で 200 回中 4 回を再現。CI の E2E が 1 回だけ落ちた原因）。
  対策：(a) 最初の標本は「DPR ÷ タブの倍率」が 0.9 未満なら矛盾として使わない（`SV.zoom.isConsistent`。OS の表示倍率が 1 の画面で有効）。(b) 倍率を変えたら、画面に反映されて高さが 250ms 落ち着くのを待ち、**落ち着いた標本でもう一度計算する**（最大 3 回。(a) で見逃した誤りもここで直る）。完了すると `html[data-sv-zoom="done"]`。
- 設定：`auto`（既定・目標高さ 720）／`off`（触らない）／`fixed`（固定倍率 1.25〜3）。

| 状態 | 見えるもの |
|---|---|
| **H**（非表示）| 映像だけ。**一時停止中でも何も出ない**（/tv と同じ）|
| **C**（操作画面）| タイトル・進行バー・時間・ボタン列。フォーカスは「進行バー」か「ボタン列」|
| **S**（スクラブ）| 進行バー（太く・赤のグラデーション・つまみ）と、目標の時刻だけ。タイトル・時間・ボタン列は隠れ、**映像は止まる**。時間切れはない |

| キー | H（非表示）| C（操作画面）| S（スクラブ）|
|---|---|---|---|
| OK | 操作画面（ボタン列の再生にフォーカス。再生/一時停止は切り替えない）| 進行バー: 再生/一時停止。ボタン列: そのボタンを押す | **確定**（目標へ移って再生・隠す。一時停止していても再生に戻る）|
| ↑ | 操作画面（ボタン列）| ボタン列 → 進行バー。進行バー → 隠れる | 取り消し（進行バーに戻る）|
| ↓ | 操作画面（ボタン列）| 進行バー → ボタン列 | 取り消し |
| ← → | 操作画面（**進行バー**。シークしない）| 進行バー: **スクラブ開始（その場で ±10 秒）**。ボタン列: ボタン間を移動（端で止まる）| ±10 秒（押しっぱなしで加速）|
| BACK | **全画面を終えて前のページへ**（9.5）| 隠れる（再生はそのまま）| 取り消し（位置はそのまま・再生が再開）|
| 再生/一時停止（Space・メディアキー）| 操作画面＋切り替え | 切り替え | — |
| 早送り・巻き戻し | スクラブ開始（現在位置から。最初の 1 回は動かさない）| 同左 | ±10 秒 |
| STOP | 離れる | 離れる | 離れる |
| そのほか | 操作画面 | 隠れるまでの時間が延びる | 無視 |

- **自動で隠れる**：最後のキーから **5.0 秒**（C のとき）。一時停止中・ポップアップを開いている間は隠れない。
- **スクラブ**：1 回 10 秒。キーを押しっぱなしにして、間隔が 150ms 以下のとき、最初の 14 回は 10 秒、その後は上限（動画の長さの約 0.55 乗。18.5 分で約 41 秒、66 分で約 81 秒）へなだらかに加速する（/tv の実測。`SV.watchCore.scrubStep`）。目標は 0〜動画の長さに収まる。確定は `video.currentTime` を目標に設定して再生。取り消しは位置を変えずに再生を再開する。
- **広告中・ライブ・シーク不可の区間**（`vjs-ad-playing` / `strp-adsactive` / `strp-adbreaking`、`vjs-live` または `duration` が有限でない、`strp-no-seek`）：スクラブに入らない（操作画面は出る）。**広告のスキップは提供しない**（N1）。
- **再生速度・画質**（右のピル）：OK で TVer 自身のポップアップ（Radix）が開き、**↑ ↓ は TVer 自身がフォーカスを動かす**（再生速度は 2 列のグリッドを 1 列にして、見た目と矢印の向きを一致させる。矢印では選ばれない）。**OK でフォーカス中の項目を選んで閉じる**（Radix は Enter では何もしないため、拡張が項目を押して Esc を渡す）。BACK で閉じる（Esc 以外の戻るキーは Esc に置き換えて渡す）。閉じても操作画面は残る。
- **リアルタイム配信**（`/live/局`。TVer の `LiveController`）：チャンネルのページは、開いただけで再生が始まり、局のタブと番組表も使うので、**開いただけでは視聴画面（劇場表示）にならない**（ページの中のプレイヤー）。プレイヤー（操作盤）にフォーカスして OK、または TVer の全画面（`f`・ボタン）で視聴画面に入る。視聴画面の見た目・操作は VOD と同じ（H/C、5 秒で隠れる）。違い：LIVE のバッジ（覆い・赤）、進行バーと時間はない、ボタン列は「停止・画質」（中央は停止ボタン 1 つ）、← → はシークしない。**停止ボタンは押すと配信が終わる**ので、進行バーの OK・メディアキーでは押さず、ボタンに合わせた OK だけが押す（`noPause`）。戻る：操作画面 → 隠す → **視聴画面をやめてページに戻る**（履歴は戻らない・配信は続く・全画面は終わる）。プレイヤーへは、タブから ↓、説明のボタンから ↑ で入れる。
- **再生が終わる**：TVer 自身の「次のエピソード」の案内（カウントダウン）が、劇場表示の中に出る。OK で次のエピソード、BACK 1 回で TVer の「閉じる」を押す（自動再生が止まり、TVer 自身が全画面を終えて、プレイヤーを最初のポスターに戻す。その後の OK は見直し、BACK は前のページへ）。案内が残ったままのときは、もう 1 回の BACK で離れる。何も押さなければ TVer の仕様で次へ進む。
- **離れる**（BACK・STOP）：全画面を終え、前のページへ戻る（`history.back()`。このタブの履歴が 1 件ならハブ）。戻った先で TVer が出すミニプレイヤー（再生中のまま離れると出る）は、すぐ閉じる（音が鳴り続けないように）。
- **時刻の書式**：`m:ss`、1 時間以上は `h:mm:ss`（`0:19` `47:55` `1:06:01`。分は 0 埋めしない）。
- **/tv との差**（意図した差と残る差。9.8）：前／次のボタンは TVer に対応するものがないので「10 秒戻る／進む」、左のグループ（チャンネル・概要・登録）はなし、スクラブのサムネイル画像はなし（時刻だけ）、広告の表示・「次のエピソード」の案内・ポップアップの中身は TVer のもの。

実装の要点：

- **操作盤の出し入れは拡張の状態だけで決める**：`html[data-sv-ui]`（H / C / S）と `html[data-sv-focus]`（bar / row）を CSS が読んで `opacity` を決める。TVer 自身の表示タイマー（2.5 秒・フォーカス中は 30 秒）・トランジション・暗い帯（スクリム）は CSS で上書きして使わない（/tv にはアニメーションも暗い帯もない）。`opacity` で隠す（`visibility` だと `focus()` できない）。
- **覆い `#sv-watch-ui`**：タイトル・進行バー・時間・スクラブの時刻を描く読み取り専用の要素。TVer の進行バーはマウス専用で、スクラブの目標を表せないため、拡張が描き直す（TVer の進行バー・時間・音量・全画面ボタンは見た目で隠す。TVer の状態は変えない）。**操作盤の直前（同じ親・同じ重なりの層）に置く**ので、host の中にあって全画面（top layer）でも見え、操作盤のポップアップは覆いの上に出る。クリックもフォーカスも受けない。
- **実フォーカス**：H・S・進行バーのときは操作盤のコンテナ（`tabindex=0`）、C のボタン列は TVer 自身のボタン（`:focus` の見た目を白地・黒文字にする）。ツールチップは /tv と同じく、アイコンだけのボタンにフォーカスしたときだけ下に出す（再生ボタンとピルには出ない）。
- **キーは TVer 自身と二重にならない**：拡張が扱うキーは `window` の capture で止めるので、TVer の `document` の keydown（←→ で ±10 秒、↑↓ で音量、Enter/Space で再生）には届かない。拡張が扱わないキー（`f` 全画面・`m` ミュートなど）は TVer にそのまま届く。サイトのモーダル（アンケート・同意。host の外）が開いている間は、視聴画面はキーに関与しない。
- 配置は /tv の実測値（`--wu`）。`html.sv-watch` の間だけ当たる CSS は `sites/tver/watch.css`、動作は `sites/tver/watch.js`、状態遷移は `common/watch-core.js`（DOM に触らず、単体テストの対象）。

### 7.6 画面上のキーボード（TVer 向け。`common/osk.js`・`osk.css`）

YouTube /tv は公式の OSK を持つので、TVer だけ。リモコンに文字入力がなくても、検索とアンケートの入力ができる。

- **開く**：検索ピルで OK（キーワード検索）。入力欄（`input`・`textarea`）にフォーカスして OK（その欄に入力）。開いている間は、すべてのキーを OSK が受ける（背景のページには届かない）。HOME はハブへ。
- **配列**：ひらがな（五十音・列＝あ行〜わ行）／カタカナ／ABC（小文字・大文字、数字、`-_.@`）。左下のキーで順に切り替える（表示は次の種類。切り替えたあともそのキーにフォーカスが残る）。数字だけの欄（`type=number|tel`・`inputmode=numeric`・`pattern=[0-9]*`）は数字キー（3 列）だけ。`゛` `゜` `小` は直前の 1 文字を変える（か→が→か、は→ば→ぱ→は、つ↔っ。カタカナも）。空白・削除・完了（検索ピルでは「検索」）。
- **操作**：十字キーで移動（端で止まる・空きは飛ばす。上下は中心に近い列へ）、OK で押す、戻る（Esc）で取り消し（検索はしない）。物理キーボードの文字も入る（開発・動作確認用。数字欄は数字だけ）。Backspace は 1 文字消し、空なら閉じる。
- **検索**：サイトのヘッダーの検索フォームに入力して送る（TVer の SPA 遷移・検索履歴はサイト任せ）。React が状態を更新するのを待ってから送り、1.5 秒たっても `/search/キーワード` にならなければ URL で直接開く。空のキーワードは検索しない。
- **入力欄**：入れた文字はその場で欄に入る（React の `input` イベント）。完了で `change`。OK でフォームは送信しない。**入力欄から十字キーで出られる**：↑ ↓ は常に、← → は文字の端（または空）にキャレットがあるときだけ（それ以外は文字の中の移動）。Esc は「戻る」。
- **入力欄は左詰め**（長いときは末尾までスクロール）。検索では、**入力欄の右端に検索アイコン**があり、押しても検索できる（リモコンでは最上段のキーから ↑ でアイコン、OK で検索。↓ で戻る）。最初のフォーカスはアイコンではなく先頭のキー。
- **初回のアンケート（TVer の必須アンケート）は、出たら自動で入力が始まる**：誕生年（4 桁）→ 誕生月 → 性別 → 郵便番号 → 「回答する」。数字の欄は、画面上のキーボードが自動で開き（数字だけ）、「完了」で次の欄が自動で開く。性別は、最初の選択肢にフォーカスし、← → で動かして OK で選ぶと次へ（Radix のラジオは Enter で選べないので、OK でクリックする）。最後は「回答する」にフォーカス。入力済みの欄はとばす。戻る（Esc）で自動の流れは止まる（あとは欄で OK でキーボードを開ける）。「回答する」は、フォームの外（モーダルの下の段）にある。数字だけの欄は、`type`・`inputmode`・`pattern` のほか、**例（placeholder）が数字だけ**でも判定する（アンケートの欄には `inputmode` がない）。
- **物理キーボード（開発用）**：打ったあと、キーを動かさずに Enter ＝ 完了。
- 見た目は /tv の検索画面に寄せた配色（#0f0f0f 地・#373737 のキー・フォーカスは白地黒文字）。アニメーションなし。

### 7.7 キャスト待機（`sites/youtube/receiver-main.js`・background）

スマホの YouTube アプリから送る（キャスト）と、自動で前面に出て再生する。

- **設定**：`youtube.receiver`（既定オフ）。オンのとき、ブラウザの起動時・設定変更時・ハブを開いたときに、YouTube /tv を**裏のタブで 1 つだけ**開いておく（受け取り役は 1 つしかなれないので、2 つ以上あれば 1 つに整える）。閉じても少しあとに開き直す。
- **前面に出す**：スマホから送られると /tv が再生画面（`#/watch`）になるので、裏のタブなら前面に出す。ハブの YouTube タイルは、裏の /tv を前面に出す。
- **ハブへ戻る**：/tv のタブは遷移も再読み込みもしない（受け取り役がいなくなる）。ほかのタブを前面に出し（なければハブを新しいタブで開き）、/tv は再生を止めてホームの画面に戻す。
- **スマホの十字キーで TVer・ハブを操作する機能は無い**（検討して削除。NOTES 3.12）。
- **最初のリンク**：ブラウザの /tv は自動では見つからないので、最初の 1 回だけ「テレビコードでリンク」で組み合わせる（OPERATIONS）。
- **実機の確認項目**：NOTES 3.12・3.14。

### 7.8 Spotify（`open.spotify.com`。`sites/spotify/`）

Web プレーヤーの画面は作り替えず、リモコンで使えるようにするだけ。

- **操作**：十字キーで空間ナビ（棚のカード・曲の行は `role=row` を 1 つの候補にする。中のリンク・ボタンは外す）。OK でカードを開く／曲の行を再生。戻る＝`history.back()`（ホームでは、ハブへ）。再生/一時停止・次・前のキーは、サイトの操作ボタン（`data-testid="control-button-…"`）を押す。検索欄は OK で画面上のキーボード（TVer と共通の `osk.js`）。画面倍率は TVer と同じ手順。
- **候補にしない**：別サイト（`open.spotify.com` 以外）へのリンク・`target="_blank"`・画面に出ない補助の要素。
- **Home**：Spotify のタブは動かさない（遷移すると音楽が止まる）。ほかのタブ（ハブ・TVer）を前面に出し、なければハブを新しいタブで開く。ハブの Spotify タイルは、開いている Spotify のタブがあれば前面に出す（なければ同じタブで開く）。
- **再生バーの棒**：再生位置・音量の本体（`input[type=range]`）は画面に出ない（`hidden-visually`）ので、フォーカスできる容器（input の label の親）に印（`data-sv-slider`・`tabindex=0`）を付ける。OK で「調整中」（`data-sv-adjusting`）になり、← → で動かす（再生位置は 10 秒、音量は 0.1）。↑ ↓・OK・戻るで調整を終える。調整中でなければ ← → は普通のフォーカス移動。早送り・巻き戻しのキーは、フォーカスに関係なく再生位置を 10 秒動かす。
- **再生中の大きな画面**（`nowplaying.js`・`nowplaying.css`）：再生バーのジャケット（`cover-art-button`）で OK、または黄色キーで開く。ジャケット・曲名・アーティスト・再生位置・再生状態を大きく出し（背景はジャケットをぼかした暗い色）、**サイトの「再生中ビュー」は使わない**（内側の作りに依存するため）。読み取りは再生バーの `data-testid` と、歌詞（`lyrics-line`。いまの行は文字色が色の変数 `--lyrics-color-active` と同じで、普通の行（`--lyrics-color-inactive`）と違うもので見分ける。分からないときは歌詞を出さない）。歌詞は、サイトの歌詞表示が開いているときだけ DOM にあるので、閉じていれば歌詞ボタンを押して開き、閉じるときに戻す。開いている間のキーは、すべてここで受ける：OK＝再生/一時停止、← →＝10 秒、↑＝前の曲、↓＝次の曲、戻る・黄色＝閉じる、Home＝ハブ。
- **画面倍率**：Spotify は TVer（720）より小さい高さ（648）に合わせて、大きく拡大する（自動のときだけ。1080 の画面で約 1.65 倍）。拡大すると画面の幅が狭くなる（約 1160px）ので、右の「再生中ビュー」の列は隠し（`data-sv-hide`）、左のライブラリは幅 300 にする（`--left-sidebar-width`）。フォーカスのリングは 4px。
- **隠すもの**：アプリのインストール・最新情報・再生状況・ミニプレーヤーのボタン（リモコンで使えない）。
- **ログイン画面**（`accounts.spotify.com`）は別サイトなので、拡張は何もしない。
- **前提・未確認**：音楽の再生には Widevine（コンテンツ保護）が必要なはずで、入っていない Chromium では再生できない可能性がある ❔。ログイン後の画面（ライブラリ・再生中の画面）は未確認 ❔（ログアウト状態の画面で確認）。

## 8. YouTube（公式 /tv）

### 8.1 起動方式 ✅✔

`youtube.com/tv` は、デスクトップ UA だと案内ページ（「youtube.com に移動します」）を出してリダイレクトする。**TV 端末の UA を与えると TV 向け UI が起動する**。そこで拡張が次の 2 つを行う。

**(a) リクエストヘッダの書換え（DNR 静的ルール `yt-ua`・常時有効）**

```json
{
  "id": 1, "priority": 1,
  "action": { "type": "modifyHeaders", "requestHeaders": [
    { "header": "User-Agent", "operation": "set",
      "value": "Mozilla/5.0 (SMART-TV; LINUX; Tizen 6.0) AppleWebKit/537.36 (KHTML, like Gecko) 76.0.3809.146/6.0 TV Safari/537.36" } ] },
  "condition": { "urlFilter": "||www.youtube.com/tv", "resourceTypes": ["main_frame", "sub_frame"] }
}
```

**(b) `navigator` の上書き（MAIN world・`document_start`。`sites/youtube/ua-main.js`）**

`navigator.userAgent` と `appVersion` を同じ UA にし、`userAgentData` を `undefined` にする（二重適用ガード付き）。

- ヘッダと `navigator` の**両方を揃えた構成**で動作を確認した ✔（片方だけの挙動は未確認）。
- UA プリセット：Tizen 6.0 を採用（ブラウザ上で起動を確認 ✔）。webOS・Cobalt・Xbox One・PS4・Chromecast の UA でも `/tv` の本体 HTML が返ることは HTTP レベルで確認 ✔。UA の切替 UI は実装していない（静的ルールと MAIN world スクリプトの組で固定。変更するには 2 ファイルを編集）。

### 8.2 検証結果（要約）✔

| 項目 | 結果 |
|---|---|
| 起動 | TV UA で TV UI が起動（`ytlr-app`）。拡張経由でも同じ（ライブスモークで継続検証）|
| 方向キー・Enter・戻る | ↑↓←→ でフォーカス移動、Enter で決定。Escape は戻る（開いたパネルを閉じて元の位置にフォーカス復帰）、Backspace も戻る（コンテンツ最上位ではガイドへフォーカスが移る）|
| Home キー | **/tv は何もしない** → 拡張が横取りする |
| スケール | 自動（root フォント = 高さ÷45）。拡張はズームしない |
| ログイン | 初回は「使ってみる」→「スマートフォンでログインする」（QR コード＋`yt.be/activate`＋コード）。**リモコンだけでログイン操作が完結**。ゲスト視聴も可 |
| 再生中 | ↑ でコントロールを表示、Esc でコントロールを隠す（再生は継続）|
| ルートでの戻る | アカウント選択画面へ（そこでは何も起きない）|

### 8.3 拡張が追加で行うこと

- **HOME**（`Home` / `BrowserHome`・追加キー）→ ハブへ。capture フェーズで横取りし、Service Worker に `sv:goHub` を送って `chrome.tabs.update` で遷移する（content script から拡張ページへ直接遷移するには `web_accessible_resources` が必要になるため）✔。
- **戻るキー長押し → ハブへ**（設定でオン。長押し中の連続 BACK は /tv に渡さない）✔。
- **通常 URL の転送**（DNR `yt-redirect`・既定オフ・設定でオン）✔：`youtube.com/watch?v=ID`（`v` が先頭のリンク。`www.`・`m.` 可）、`youtu.be/ID`、`youtube.com/`（ルート）を `youtube.com/tv#/watch?v=ID` / `youtube.com/tv` へ。他のパス（`/results` 等）は転送しない。`v` が先頭でない URL は正規表現の上限（コンパイル後 2KB）に収まらないため非対応。

### 8.4 制約・リスク

- UA 判定が変わると /tv が起動しなくなる恐れ（R1）。ライブスモークで早期検知する。
- TV 端末への UA 偽装は YouTube が想定する利用形態ではない。**個人利用の範囲**とし、広告・視聴制限・年齢制限の回避は行わない（R2）。
- 初回ログインにはスマートフォン（別端末）が必要。ログイン状態はブラウザのプロファイルに保持される（拡張は認証情報を扱わない）。

### 9.3 フォーカス対象と除外

- **対象**：`a[href]`、`button`、`input`、`summary`、`[role="button" / "link" / "tab" / "menuitem" / "switch" / "checkbox" / "radio"]`、`[tabindex]`（`-1` を除く）。文字入力欄（`text` 等の `input`・`textarea`）も対象で、OK で画面上のキーボードが開く（7.6）。
- **除外**：不可視（幅・高さが 8px 未満、`visibility: hidden`、`display: none`、`inert`、`aria-hidden="true"`）、`header` 内、`footer` 内、**パンくず**（ページ下部の `AppLayout_breadcrumb`。`main` の外にあり、戻るは Esc で足りる）、アプリバナー・カルーセル矢印・「アプリで視聴する」、`iframe` 内、外部リンク（`tver.jp` 以外。`help.tver.jp`・`schedule-drama.tver.jp` などのサブドメインも含む。拡張が動かず、外へ出ると戻れなくなるため）、新しいタブで開くリンク（`target="_blank"`。番組ページのバナーなど）、無効（`disabled` / `aria-disabled`）。

### 9.4 空間ナビゲーションと遷移

| 項目 | 仕様 |
|---|---|
| 候補選択 | 方向ごとに「中心が進行方向にある」候補を抽出し、2 パスで選ぶ。**パス 1**：同じ行／列に重なる候補のみ。`score = 向かい合う辺の距離 + 2 × 直交方向のずれ`。**パス 2**（パス 1 が空のとき）：重ならない候補。`score = 距離 + 6 × ずれ`。**パス 1 に候補がなく、隣の領域（レール）があるときは、パス 2 より先に隣の領域へ出る**（横にスクロールして見えなくなった別の行の要素へ飛んで、レールへ出られなくなるのを避ける）。該当なしなら**移動しない**（ラップしない）。同点は距離、DOM 順 ✔ |

| 縦移動の列保持 | 行（棚）の外（ビルボード・ボタン・番組ページなど）の上下移動では、直前の横位置（sticky x）に近い列を選ぶ（行の間は 9.4c）。**基準座標は次の縦移動の開始時に、その要素の「いまの位置」から取り直す**（行ごとに横スクロール量が違い、スクロール中の古い座標だと列がずれるため）✔ |
| スクロール | `scrollIntoView` は使わず自前。**横**：最寄りの `overflow-x` コンテナだけを即時にスクロール（コンテナ幅の 12%・24〜160px の余白を残す）。**縦**：フォーカス要素が画面の 6〜94% に完全に入り、中心が 20〜80% にあれば動かない。外れたら中央へ（スムーズ。押しっぱなしは即時）。固定／sticky 領域（`header`・`nav`）内では画面をスクロールしない ✔ |
| 領域 | `rail`（`nav`）／`content`／`modal`（`[role="dialog"]` 等）。端で方向キーを押すと隣の領域へ（← でレール、→ で直前のコンテンツ）。modal が開いている間は modal 内だけが候補で、外にフォーカスがあれば modal の中へ入る ✔ |
| 初期フォーカス | 遷移後、DOM が 250ms 安定してから実行。**コンテンツ領域の `main` の内側に候補が現れるまで待って再試行**（最大 10 秒。レールや、`main` の外の補助的なリンクには先にフォーカスしない。4 秒を過ぎたら `main` の外でもよい）。戻る・再訪で記憶があればその要素を復元（4 秒まで待つ）。**操作を始めた後は奪わない** ✔ |
| 遷移の検知 | Navigation API（`navigatesuccess`）＋`popstate`＋`hashchange`＋500ms ポーリング ✔ |
| フォーカス記憶 | ルート（`pathname + search`）ごとに最後のフォーカス（`href`・ラベル・縦位置）を保存。`sessionStorage` にも保存するので、フルリロードを伴う遷移でも復元できる ✔ |
| 喪失からの復帰 | React の再描画でフォーカス要素が消えたら、記憶から復元して初期フォーカスにフォールバック ✔ |

### 9.4b 詳細ポップアップ（TVer 標準の詳細表示）

番組（シリーズ）・エピソードページのエピソード一覧のカード（`SeasonEpisodeListItem_popupContainer`）は、マウスを載せると TVer 自身が**詳細ポップアップ**（サムネイル・タイトル・配信終了・あらすじ・いいね／あとでみる／シェア）を出す。実装は React の `onMouseEnter` / `onMouseLeave`（`mouseover` / `mouseout` から導かれる）で、CSS の `:hover` ではない。リモコンにはマウスがないので、**フォーカスが入ったら host に `mouseover`、出たら `mouseout` を送る**（`content.js`。拡張は DOM を作らない）。調べた結果（NOTES 3.9）：

- **TVer 自身の端末判定（`navigator.userAgent`）が「その他」のときだけ出る**。Windows・macOS の Chrome は「その他」だが、**Linux の Chrome/Chromium は「Android PC」と判定され、出ない**（キオスクやミニ PC は Linux のことが多い）。そこで Linux の Chromium のときだけ、ページ側の `navigator` を Windows の Chrome にする（`sites/tver/ua-main.js`。MAIN world・`document_start`。ヘッダは変えない）。Windows・macOS では何もしない。副作用：レールに「マイページ」が増える（Windows の Chrome と同じ画面になる）。
- ポップアップを持つのはエピソード一覧だけ。ホーム・カテゴリのカード、ビルボードには TVer 標準の詳細表示がない（そこには出さない）。クラス名が変わると出なくなるだけで、操作は変わらない。
- **置きっぱなしの本物のマウス**が、フォーカスのポップアップと食い違わないよう、本物（`isTrusted`）の `mouseover` / `mouseout` は host に通さない。
- 表示はサイトのもの。出るまでの遅延（0.2 秒）とフェードは、/tv に合わせて 0 にする。
- ポップアップを出している間は、カードはその下に隠し（拡大しない）、**フォーカスのリング（6px）はポップアップに付ける**。
- ポップアップの中のリンク・ボタン（カードと同じ遷移先、ログインが要るボタン）はフォーカス対象から外す（`isExcluded`）。フォーカスは常にカードで、Enter でエピソードへ。
- 番組ページの 2 列（情報 | エピソード一覧）は、右の列が内容の幅で押し広げられて画面からはみ出さないよう `grid-template-columns: 40% minmax(0, 1fr)` にし、右の余白を 2u にする（ポップアップはカードより 28px 外側まで広がる）。

### 9.4c 行（棚）のスクロールと移動（/tv に合わせる）

`common/rows.js`（純粋な計算）と `sites/tver/content.js`（`scrollRow` / `retargetRow`）。`spatial-nav` の `scroll`（既定のスクロールの代わり）と `retarget`（移動先の差し替え）オプションで入れている。

| 項目 | 仕様（/tv の実測。NOTES 3.9）|
|---|---|
| 縦 | フォーカス中の行の**見出し**（なければ行の上端）を、画面の上から **15%**（高さ 720px で 108px）に固定する。前の行は上へ流れ、上部バー（検索ピル）の下で隠れる。次の行の見出しと上部が下から覗く。**アニメーションなし**（即時）|
| 横 | 先頭のカードは 1 枚目の位置、**2 枚目以降は 2 枚目の位置**（x = 6.5u + 22u + 1.5u = 480px）にフォーカスを保ち、行のほうが 1 枚ぶん（376px）ずつ動く。即時（アニメーション中に次の上下移動の列を測るとずれるため）。/tv で実測したのは右へ進むときで、左へ戻るときも同じ規則にしている 🔶 |
| 上下で別の行へ | その行で**最後にフォーカスしたカード**（初めてなら先頭のカード）へ。列は引き継がない。その行の外にある非カードの要素（バナーなど）は、幾何的な移動のまま通る |
| 検索ピルへ | 上へ進んで、**流れの中でそれより上に別の候補がないとき**だけ（ビルボード・先頭の行から）。行が上へ流れて隠れたあとは、固定のピルが幾何的に一番近くなるため、上に候補があれば先にそちらへ |

/tv との意図した違い：(1) ガイドで上下するだけでは切り替えない（7.4）。(2) 画面の右へ続く行は TVer の行のまま（/tv の継続読み込みはしない）。

### 9.5 プレイヤー（視聴画面の仕組み）

- TVer のプレイヤーは **STREAKS Player（Video.js 8 ベース。`chromeless: true`）** ✔。操作盤は Video.js の `.vjs-control-bar` ではなく、**TVer 自身の React 製コンポーネント `VodController`**（`tabindex="0"`・`data-fullscreen`）で、`<video>` を含む `.video-js` の**兄弟**として描かれる。Shadow DOM は使っていない ✔。実サイトの構造（保存したページ・実プレイヤーで確認 ✔）：

  ```
  Episode_player > PlayerLayout_host[js-fullscreen-target][data-mini-player] > aspectRatioWrapper > container
    > PlayerLayout_jail（isolation・overflow: hidden・mask-image・角丸）> MiniPlayerLayout_* > EpisodePlayer_*
      > .video-js.streaks-player（video）+ ポスター（#episode-play）+ VodController（-10・再生・+10・音量・時間・速度・画質・全画面）
  ```

- **動作に使うのは、TVer 自身が明示している属性と ARIA ラベルだけ**（`selectors.js` の `watchParts`）：`[js-fullscreen-target]`（全画面の対象）、`[data-fullscreen]`（操作盤）、`button:has(svg[aria-label="再生"|"一時停止"|"10秒戻る"|"10秒進む"|"全画面"…])`、`button[aria-label="再生速度の選択"|"画質を選択"]`、`[role="dialog"][data-state="open"]`、`#episode-play`、`button[aria-label$="を再生"]`（次のエピソード）・`button[aria-label="閉じる"]`。クラス名（CSS Modules）は見た目（`watch.css`）にしか使わない。見つからない部品があれば何もせず、TVer 自身のキー操作がそのまま使える。
- **旧方式（自前の HUD＋擬似フルスクリーン）で、実サイトで起きていた干渉**（調査 2026-10-19。NOTES 3.10）：(1) `PlayerLayout_jail` の `mask-image` は `position: fixed` の子孫まで切り取るので、映像が元の 752x423 のまま残り、HUD だけが全面に出た。(2) 全画面を `<html>` に要求したので、TVer 自身の全画面（`[js-fullscreen-target]`）とは別になり、TVer の `f` キーが拡張の全画面を終えて HUD を閉じた。(3) `visibility: hidden` で他を隠したため、TVer 自身の操作盤・次のエピソードの案内・広告の表示が消えた。(4) `<video>` を直接操作して再生したので、初回のアンケート（回答しないと再生されない）を飛ばして再生できた。(5) 閉じたあとの ↓ のスクロールや戻るで、TVer がミニプレイヤーに切り替えた。→ **TVer 自身のプレイヤーと全画面をそのまま使う**方式に作り直した。
- **開始**：ポスターの再生ボタン（`#episode-play`。TVer が autoFocus する。拡張の初期フォーカスも同じ）で OK → TVer 自身が再生を始める（初回はアンケートが出る。キーボードで入力する。拡張はモーダルの間キーに関与しない）。操作盤が出た（または再生が終わった）ら `html.sv-watch` を付けて視聴画面にする。ミニプレイヤー（`data-mini-player="true"`）のときは何もしない。
- **劇場表示（CSS・常に当てる）**：`html.sv-watch` の間、`[js-fullscreen-target]` を `position: fixed; inset: 0`（z-index はモーダル(50)の 1 つ下）にし、TVer の `:fullscreen` の規則と同じ配置（16:9 を画面に収める）を当てる。**`PlayerLayout_jail` の `mask-image`・`overflow`・角丸を外す**。`html`・`body` は `overflow: hidden`（スクロールで TVer がミニプレイヤーを出さないように。ホスト自体が固定で画面内にあるので、スクロールされても出ない）。全画面にならなくても、全画面のときと同じ見た目になる。
- **全画面**：設定 `tver.nativeFullscreen`（既定オン）のとき、視聴画面になったら **TVer 自身の全画面ボタンを `click()`**（TVer が `[js-fullscreen-target]` に `requestFullscreen` し、`data-fullscreen`・`:fullscreen` の CSS・アイコンが TVer の状態のまま変わる）。Fullscreen API は**ユーザー操作の直後（約 5 秒）でないと拒否される**ので、押せなかったとき（自動再生・アンケートの入力が長引いたとき）は、**次の最初のキー操作**で押す（Esc は操作にならない）。拒否される要求は出さない。全画面の間は **Keyboard Lock で Esc を拡張が受ける**（ブラウザは全画面中の Esc を奪って全画面を終えてしまう。ロック中は Esc の長押しで全画面を終える）。TVer 自身の `f` で全画面を出入りしても視聴画面は保たれる（劇場表示になる）。ブラウザの全画面が終わっても視聴画面は終わらない。
- **離れる**（BACK・STOP）：全画面を終え、`history.back()`（履歴が 1 件ならハブ）。`html.sv-leaving` の間、TVer がミニプレイヤーを出しても見せず、**「閉じる」を押して破棄する**（最大 4 秒待つ）。
- ❔ **再生は日本国内IP・DRM・コーデックに依存**する。開発用サンドボックス（国外IP）では再生 API（`playback.api.streaks.jp`）が 403 になる。**実サイトの JS・Streaks SDK のまま、この API だけを偽の応答（ローカルの webm 1 本）に差し替えて再生させ、実 DOM で視聴画面を確認している**（ライブテスト。偽装は検証用で拡張には入っていない）。DRM・HLS・広告は実機で確認する（NOTES 4）。
- ❔ **実機で確認すること**：全画面中の Esc を Keyboard Lock で受けられるか（受けられなければ、最初の Esc が全画面を終えるだけで操作は続く）、約 5 秒のユーザー操作の窓、広告（`strp-ad-module` は z-index 10000 で覆いの上に出る想定）、リモコンの `key`/`code`（TVer 自身の keydown は `e.code` を見る）。
- 既知の制限：リアルタイム配信の「追っかけ視聴」（TVer にログインした人だけの機能。進行バー・最初から見る・速度）は操作を作っていない（シークはしない）。初回のアンケートは、出たら自動で画面上のキーボードが開く（7.6）ので、リモコンだけで答えられる。字幕の ARIB 表示は操作できない。

### 9.7 サイト変更への強さ

TVer の画面が変わったとき、どこまで動き続けるか。**再現ページの HTML を変形して同じ操作を試す実験**で確かめた（Chromium 141、2026-10-18。自動テスト `tests/e2e/tver-resilience.test.mjs` に残してある。経緯は NOTES.md 3.5）。実サイトの将来の変更を予測するものではなく、「この種類の変更なら耐える／耐えない」の目安。

| 変更の種類 | 結果 | 備考 |
|---|---|---|
| CSS Modules のハッシュが変わる（デプロイごとに起こる）| ✔ 変わらず動く | クラスは `[class*="Name_part__"]` で一致させる |
| 番組・行・カードの数や並びが変わる | ✔ 変わらず動く | 空間ナビは座標で判定し、DOM 順に依存しない |
| 寸法が変わる（カードの幅・高さ・間隔、ビルボードの幅）| ✔ 変わらず動く | 上下移動の列も保たれる |
| ダークテーマの保存キーが変わる | ✔ 変わらず動く | DOMContentLoaded 後に `html.dark` を確認し、なければ付ける（保険）|
| プレイヤーのクラス名が変わる（`video-js` `streaks-player` `vjs-*`）| ✔ 動く（見た目も保たれる）| 視聴画面は属性・ARIA で探す。失われるのは広告・ライブ・シーク不可の検知だけ |
| エピソードの URL が変わる（`/episodes/` 以外）| ✔ 動く（見た目も保たれる）| `data-episode-page="true"` でも判定する（9.1）。この保険を入れる前は、視聴画面・初期フォーカスがすべて使えなくなった |
| プレイヤーのコンポーネント名が全面的に変わる（`PlayerLayout_` `VodController_` `Speed_` など）| △ 動くが劣化 | キー操作・全画面・ポップアップ・スクラブは動く（属性・ARIA で探す）。見た目（配置・フォーカスの白地・劇場表示のマスク解除）は TVer 標準に戻る |
| 左レールが `<nav>` でなくなる | △ 動くが劣化 | レールへは行ける。現在のページを優先する動作は失われる |
| カード・ビルボードのコンポーネント名が変わる | △ 動くが劣化 | カードの拡大・角丸のリングが失われる（フォーカス枠自体は出る）|
| コンポーネント名が全面的に変わる | △ 動くが劣化 | 操作はできる。ヘッダーの検索・設定、カルーセル矢印、アプリバナーが再び見え、矢印ボタンにもフォーカスが止まる |
| ダークテーマのキーとクラス名の両方が変わる | ❔ 実サイトでないと分からない | 再現ページでは本文も読めたが、実サイトの文字色は部品ごとのトークンで決まるため、暗い背景に暗い文字になる恐れがある |
| DOM 構造の全面的な作り直し、プレイヤーの入れ替え | ❌ 追従できない | `selectors.js` と `tver.css` の更新が必要 |

- **崩れ方**：スキン（見た目）が崩れても、フォーカス移動と視聴画面のキー操作は動くようにしてある。フォーカス候補の収集は汎用セレクタ（`a[href]` `button` ARIA ロール `tabindex`）と座標だけで行い、サイト固有のクラス名は見た目（非表示・拡大・リング）と初期フォーカスの優先順位にしか使わない。
- **既知の弱点**：広告の検知は `vjs-ad-playing` `strp-adsactive` `strp-adbreaking` `strp-no-seek` `vjs-live` のクラス名に依存する。変わると、広告中でもスクラブに入れてしまう恐れがある（TVer 自身は広告中のシークを無効にしている）（広告を飛ばす機能は作らない方針（N1）なので、実機で検知できているか確認し、ライブスモークで監視する）。
- **気づく方法**：`LIVE=1 npm run test:live`（実サイトのスモーク）。**自動では回していない**ので、ときどき手で実行する（定期実行は次フェーズで検討）。
- **直す場所**：サイト固有のセレクタは `sites/tver/selectors.js` と `tver.css` に集約している。
- **YouTube**：公式 /tv をそのまま使うため、画面の変更は公式が吸収する。壊れうるのは User-Agent の判定が変わったとき（R1）で、ライブスモークで検知する。

| R4 | TVer 再生が国内IP・DRM・コーデックに依存 | 非ブランド Chromium で再生不可の恐れ | 実機で最初に再生確認。不可なら製品版 Chrome（B／C）| ❔ |
| R5 | Chrome 137 以降の製品版で `--load-extension` が無効 | 導入方法が限定される | OPERATIONS.md の B／C。A は Chromium／Chrome for Testing | 緩和 |
| R6 | Home／Back 等をブラウザが先に処理 | キーが届かない | capture＋`preventDefault`、診断ページ、キー割り当て、OS 側の割当 | ❔ 実機 |
| R7 | CEC リモコンのキー・リピート間隔が想定外 | 誤操作・暴走 | リピート上限 12回/秒、診断ページで間隔を確認、キー割り当て | ❔ 実機 |
| R8 | 全画面中に Esc をブラウザが奪う | 戻る操作が 2 回必要になる | Keyboard Lock で Esc を拡張が受ける。使えなくても劇場表示（D7）で操作は続く | ❔ 実機 |
| R9 | 新規タブ／ポップアップがキオスクで開く | 戻れなくなる | 未対応（次フェーズ）。外部リンクはフォーカス対象から除外済み | 残 |
| R10 | 広告（IMA）再生中の視聴画面の挙動 | シークで破綻 | 広告クラスを検知しスクラブ無効。広告の表示は TVer 自身のもの（隠さない）| ✔ 再現／❔ 実機 |
| R11 | Service Worker の停止（MV3）| 状態喪失 | 状態は `storage` に置き、SW はステートレス | ✔ |
| R12 | DNR の `regexFilter` は 2KB（コンパイル後）まで | 転送ルールが無効になる | 単純な式にする。`v` が先頭でない URL は非対応 | ✔ 緩和 |
| R13 | 画面倍率の二重適用（要求の同時送信、読み込み直後の古い標本）| 画面が過大に拡大（2.25 倍）| 要求は順番に出し、倍率を変えたら落ち着いてから再確認（7.3）| ✔ 解消（読み込み直後の古い標本は CI で発覚。再現・修正・テスト済み）|
